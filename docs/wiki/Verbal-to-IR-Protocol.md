# 口述 → IR 生成协议（v1）

> 团队成员按本协议提供口述，张鹏的 AI 工作分身（Hermes Agent）生成用例 IR。
> 这是一份**操作协议**——照做就能得到可执行的自动化用例，不需要懂框架内部。

## 一句话流程

```
你口述测试点 → AI 生成 IR 草案（缺信息会追问）→ 你说"入库执行" → 自动执行 → 报告
```

---

## 1. 你的输入：口语即可

说什么都行，最好包含三要素（缺了 AI 会追问，不会瞎猜）：

| 要素 | 说明 | 口语示例 |
| --- | --- | --- |
| **测什么** | 被测功能/页面 | "登录页"、"上传文件"、"连错密码" |
| **怎么操作** | 操作序列（可省略，AI 推断） | "输错三次再输对的" |
| **预期怎样** | 正确行为（最重要，不可缺） | "应该提示锁定"、"不能暴露用户存在" |

### 口语范例（真实历史，均已入库执行通过）

- "测一下登录，密码错误的情况"
- "什么都不填直接点登录，应该提示要输用户名密码，不能直接过"
- "故意输错三次密码，账号要锁住，这时候就算输对密码也应该进不去，提示锁定"
- "用一个不存在的用户名登录，应该也提示用户名或密码错误，不能暴露这个用户到底存不存在"

### AI 的追问时机（保证不猜的唯一机制）

- 预期行为你没说清：会问"预期提示文案大概是什么？"
- 数据来源不明：会问"用什么账号测？测试数据谁造？"
- 涉及真实系统：会问"被测系统地址？账号？"

**你不需要懂 selector/断言/数据集——这些全部由 AI 生成，你只审核语义对不对。**

## 2. AI 的产出：IR 草案（你审核的东西）

AI 会把口述翻译成 YAML（写入 `cases/<分组>/tc_<功能>_<序号>.yaml`），你只需核对
4 个语义点：

```yaml
source: "口述: <你的原话，一字不改>"     # ← ① 追溯锚点：这是不是你说的
title: <一句话概括>                       # ← ② 标题：概括对不对
steps: <操作序列>                          # ← ③ 步骤：和你描述的操作一致吗
assertions: <断言列表>                     # ← ④ 断言：预期行为转译对不对
```

技术字段（channel/quad/data_ref/threshold）AI 自动定，不放心可问，但不审也不影响。

## 3. 断言级别选择规则（AI 内部规则，透明公开）

| 口述里的预期 | AI 用的断言 | 为什么 |
| --- | --- | --- |
| "应该提示/显示 xxx 文案" | `text_visible`（确定性 1°） | 文案可用选择器精确断言，零 AI 成本零幻觉 |
| "页面应该长这样/是这个状态" | `visual_state`（VLM 2°） | 视觉语义，5-6s/题 |
| "是不是 xx 问题/归因" | `noul`/`choice`（Laya 3°） | 概率/分类判断，10ms 级 |
| "不能出现 xxx" | `text_visible` + `negated: true` | 反向断言（如用户枚举防护） |

优先级原则：**能用 1° 确定性的绝不用 AI**——AI 只兜底确定性表达不了的场景。
一条用例通常 = 1° 确定性 + 1 条 2° VLM 兜底（双保险）。

## 4. 数据规则

- 测试数据**永远不写进用例**，放 `data/datasets.yaml` 的 tag 里，用例用 `data_ref` 引用
- 口述提到具体账号/密码 → AI 建新 tag
- 涉及状态污染的（如锁定）→ AI 自动加 `postconditions` 清理钩子，保证用例可重复执行

## 5. 执行与反馈

你说「入库执行」后 AI 会：

1. 写入 `cases/` + git 提交（IR 即资产，commit 即审计记录）
2. 立即执行（真浏览器 + 三级判定 + 置信度路由）
3. 回给你：每条断言的引擎/值/置信度/路由结果 + HTML 报告路径
4. 报告可直接转发（截图内嵌，自包含单文件）

## 6. 修订闭环

草案或执行结果不满意：

| 你说 | AI 做 |
| --- | --- |
| "把预期改成 xxx" | 改 assertions 重新确认 |
| "再覆盖一个场景：xxx" | 新增用例（同 source 追溯） |
| "这个断言太多了" | 精简并说明每条为什么留 |
| "为什么这条转人工了" | 解释置信度路由原因（conf 值+证据） |

## 7. 当前边界（诚实声明）

- 生成层是**对话中的 AI**，不是框架内自动化——`pipeline/` 自动生成是 M1 计划
- 框架当前支持 Web 通道（Playwright 驱动系统 Chrome）；Electron 通道在 M2 计划
- `--external --base-url http://xxx` 可打真实系统（需提供账号与数据来源）

## 附：一条口述的完整转化实例

口述："用一个不存在的用户名登录，应该也提示用户名或密码错误，不能暴露这个用户到底存不存在"

AI 识别：用户枚举防护测试点 → 双向断言（正向：文案一致；反向：不出现"不存在"）

```yaml
id: tc_login_005
title: 登录-不存在的用户名-模糊提示不暴露账号存在性
source: "口述: 用一个不存在的用户名登录，应该也提示用户名或密码错误，不能暴露这个用户到底存不存在"
data_ref: login_ghost_user
steps:
  - {action: nav, path: "/login"}
  - {action: fill, selector: "#username", value: "$ghost_user"}
  - {action: fill, selector: "#password", value: "$any_pwd"}
  - {action: click, selector: "button[type=submit]"}
  - {action: wait_visible, selector: ".error-msg", timeout_ms: 5000}
assertions:
  - kind: text_visible
    selector: ".error-msg"
    expected: "用户名或密码错误"
  - kind: text_visible
    selector: ".error-msg"
    expected: "不存在"
    negated: true              # ← 反向断言：绝不能出现"不存在"暴露账号存在性
  - kind: visual_state
    prompt: "页面是否停留在登录页并显示与密码错误一致的模糊提示（没有出现'用户不存在'之类暴露账号存在性的文案）？只答 yes 或 no。"
postconditions: []
```

执行结果（2026-09-23）：3/3 断言全过（确定性 ×2 + VLM ×1），用例 passed。
