id: tc_login_001              # 必填，^tc_[a-z0-9_]+$
title: 登录-错误密码-停留登录页并提示
source: "口述: 测一下登录，密码错误的情况"   # 必填，原始输入文本（追溯锚点）
req_ref: null                 # 可选，需求编号
priority: P0                  # P0|P1|P2，默认 P1
channel: web                  # web | electron | api
quad:                         # 四元组
  actor: 登录页
  action: 提交错误密码
  object: 登录表单
  preconditions: ["用户 $user 存在且启用"]
data_ref: login_invalid_pwd   # 可选，data/ 工厂 tag；用例不内嵌数据
steps:                        # 声明式动作，min 1 条
  - {action: nav, path: "/login"}
  - {action: fill, selector: "#username", value: "$user"}
  - {action: click, selector: "button[type=submit]"}
  - {action: wait_visible, selector: ".error-msg", timeout_ms: 5000}
assertions:                   # min 1 条，每条声明判定级别
  - kind: text_visible        # 确定性：selector 文案包含
    selector: ".error-msg"
    expected: "密码错误"
  - kind: visual_state        # VLM：结构化提问 + threshold
    prompt: "页面是否呈现登录失败且仍停留在登录页？"
    threshold: 0.9
  - kind: noul                # System One：0-1 概率题
    question: "当前失败归因是否为'产品缺陷'？"
    threshold: 0.9
postconditions:
  - cleanup_tag: TEST_AUTO_   # 数据还原钩子

id: tc_d04_p0_001
title: 多步算术
source: "大模型测试用例集 v1 D04-P0-001：验证模型能正确完成多步算术（折扣+优惠券）"
req_ref: "D04-P0-001"
priority: P0
channel: api                  # API 通道：HTTP 调用 LLM
quad: {actor: 大模型, action: 数学计算, object: 数学问题}
data_ref: d04_multi_step      # prompt 走数据工厂，用例不内嵌
steps:
  - {action: api_call, prompt: "$prompt"}
assertions:
  - kind: response_contains   # 确定性：关键词匹配
    keywords: ["130"]
    min_match: 1
  - kind: noul                # AI 判定兜底
    question: "模型是否正确计算出最终价格130元（200×0.8-30=130）？只答 yes 或 no。"
    threshold: 0.9

步骤类型（steps）

action 字段 通道 说明
nav path web/electron 导航（web）/窗口切换（electron）
fill selector, value web 填充；$var 引用 data_ref 数据集字段
click selector web 点击
select_option selector, value web 下拉选择
wait_visible selector, timeout_ms=5000 web 等待元素可见（禁止 sleep）
api_call prompt, system_prompt? api 单轮 LLM 调用；$var 引用数据集字段
api_followup prompt api 多轮对话追加用户消息（复用上文 messages）
api_tool_call prompt, tools api 带工具定义调用（OpenAI function schema）
api_stream prompt, system_prompt?, repeat=1 api 流式调用（stream=true，收完比对）；v0.2.7 加 repeat 字段（1-20，多样本 P95）
process_probe 全部 probe, task_id?, node?, root? 工序域探针：在动作执行时即时采集工序状态（v0.5.0 新增）；task_id: "@latest" 按落盘 mtime 定位新建任务（id 是动态 UUID）

断言类型（assertions）

kind judge 引擎 专有字段 适用
text_visible deterministic selector, expected, negated DOM 文案
attribute deterministic selector, name, expected, negated DOM 属性
visual_state vlm（mlx-vlm） prompt, threshold=0.9 页面视觉状态
noul / choice / score systemone（laya-mlx） question, options(choice 必填), threshold 语义判定/归因/量表
response_exact deterministic expected, case_sensitive L1 精确匹配（数学/事实）
response_contains deterministic keywords, min_match=1 L2 关键词匹配
response_not_contains deterministic forbidden L4 反向验证（安全性）
response_json_schema deterministic required_fields, expected_values L3 JSON 结构
tool_call_params deterministic expected_function, expected_params 工具调用参数
response_time deterministic max_seconds 性能延迟断言
response_ttft deterministic max_ms=3000 流式首 token 延迟（D14；非流式调用转人工）
response_ttft_p95 deterministic max_p95_ms=3000 流式 P95 首 token 延迟（D14 扩展；v0.2.7 多次采样 1-20 次）
response_length deterministic min_chars, max_chars 回答字符数区间（D15 字数约束）
visual_regression deterministic baseline, min_similarity=0.98, require_same_size 截图 SSIM 像素回归（v0.5.0 新增）
process_state deterministic rule / from_probe, expect, task_id?, node?, min_severity? 工序状态机判定（v0.5.0 新增，零 AI token）
agent_verify agent（Agent-as-Judge） objective, threshold=0.9, max_steps=6, system_prompt? 自主取证型判定：judge 自己调只读工具查证据后下结论（v0.4.0 新增）

工序状态机判定（process_state，v0.5.0）

定位：能用 1° 绝不用 AI。状态机判定是纯结构比对，不该让模型推理算术。

两种模式，二选一：

模式 字段 含义
规则查 rule 按规则名查违规清单（见 process_truth.RULES，9 条）
探针判 from_probe 基于 process_probe 步骤采集的结果判定 
# 规则查：链顺序不变式（照搬 node-machine.ts:12 语义）
- kind: process_state
  rule: done_after_pending_breaks_chain_order
  expect: none        # none=条件必须成立；any=条件必须不成立（反守门员）
  min_severity: all   # high/medium/low/all（low 是观察项，默认不阻断）

# 探针判：观察到的迁移
- kind: process_state
  from_probe: "transition:ready>running"

探针判定式：status_eq: / status_in: / index_eq: / output_count_ge: / has_validation_ok / transition:<from>><to>（需 ≥2 次探针）。

降级语义：工序目录不存在 / 规则名未知 / 探针缺失 → value=0.5, confidence=0.5 → route() 转人工仲裁。绝不判通过——没有可比对象就没有结论。

落地见 docs/nlaut-cecoder-judge-benchmark-gap-analysis.md §5.3–5.6。

Agent-as-Judge 判定（agent_verify，v0.4.0）

与上表所有断言的本质差异：证据不是由通道预先塞进 Evidence， 而是 judge 自己在运行时调工具去取。

项 说明
判定目标 objective（judge 的取证任务描述，会被写进 system prompt）
可用工具 6 个只读工具：query_db / http_probe / read_log / read_file / inspect_trace / list_registry
终止条件 模型不再请求工具（出结论）/ max_steps 耗尽 / 端点异常
置信度 模型自评 High/Medium/Low，强制封顶 0.85
路由结果 因 0.85 < 0.9 自动裁决线，route() 必定判 human_review
降级 端点不可用 / 无 key / 步数耗尽 → confidence=0 + raw.degraded，绝不误判为通过

环境变量：

  • NLaut_AGENT_JUDGE_MODEL — 指定模型（默认 deepseek-v4-flash）
  • NLaut_AGENT_JUDGE_TOOLS — 逗号分隔的工具名子集，用于做「有无工具」的消融对照

落地位置见 docs/agent-as-judge-design.md（接口设计）与 docs/agent-as-judge-poc-plan.md（验证方案）。

规则

  1. source 非空——任何用例必须能追溯到输入文本。
  2. choice 断言必须提供 options（校验器强制）。
  3. 未列出的 action/kind 一律校验失败（Pydantic 判别联合）。
  4. IR 是唯一事实源；gen/ 代码永远可由 IR 重建。
  5. API 用例不内嵌 prompt 值——prompt 走 data_ref 数据工厂（$var 引用），保证模型无关。
  6. 确定性断言（L1-L4）优先，AI 判定（noul/choice/score）只兜底断言不可表达的场景。
